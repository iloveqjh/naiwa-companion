# 开发指南

## 构建与目录

本项目依赖 Windows 自带的 .NET Framework 4.x 编译器，使用 C# 5 兼容语法，不需要 NuGet 包。运行 `scripts/Build.ps1` 生成 `dist/NaiwaCompanion.exe`。

| 文件 | 职责 |
| --- | --- |
| Program.cs | 命令行、单实例、错误处理 |
| AssetDownloader.cs | 原作者素材下载、校验、准备窗口 |
| Animation.cs | 视线目标、缓动、眨眼、戳肚子、拖动及动作状态 |
| Theme.cs | 读取素材包、按需解码、16 帧缓存、绘制内置演示 |
| ThemeManifest.cs | 多主题动作清单、独立帧率和区域校准 |
| Painter.cs | 眼部和肚腹局部变形、缩放、倾斜、透明画面合成 |
| Desktop.cs | Windows 透明窗口与前台全屏检测 |
| PetForm.cs | 鼠标事件、菜单、声音、托盘、位置与窗口生命周期 |
| Preferences.cs | 独立设置与原子保存 |
| SelfTests.cs | 行为与画面保护测试、预览输出 |

## 命令行

```text
NaiwaCompanion.exe
NaiwaCompanion.exe --assets "D:\素材文件夹"
NaiwaCompanion.exe --download-assets "D:\素材文件夹"
NaiwaCompanion.exe --self-test "D:\测试输出"
NaiwaCompanion.exe --assets "D:\素材文件夹" --self-test "D:\测试输出"
NaiwaCompanion.exe --assets "D:\素材文件夹" --render "D:\预览输出"
NaiwaCompanion.exe --probe "D:\窗口状态.txt"
NaiwaCompanion.exe --quit
```

程序为窗口子系统，命令行不会等待它结束；自动化测试应使用 `Start-Process -Wait -PassThru`。`--self-test` 的退出码为 0 表示通过，结果写入 `results.txt`。测试不会覆盖用户设置。测试会短暂创建本程序自己的透明窗口来验证窗口属性和 GDI 资源释放。

`--download-assets` 是显式联网下载命令，只访问清单中固定版本的原作者素材，下载成功退出码为 0，失败为 1，并在目标目录写入 `download-error.txt`。正常桌宠模式没有后台联网轮询。

`--probe` 只读取本程序的主窗口是否存在、是否可见及所在区域；`--quit` 只关闭本程序，不关闭原版奶蛙或其他软件。

## 原版兼容包

`素材.nwp` 是 ZIP 文件。程序只按名称读取内部条目，不会把条目解压到系统目录。元数据结构如下：

```json
{"width":288,"height":368,"fps":30,"frames":422,"blinkFrames":7,"blinkFps":30}
```

- `look/00.png`：原图待机；其他 look 帧并非连续二维跟随所必需。
- `blink/0/00.png` 至 `06.png`：原版中性眨眼。
- `laugh/0000.png` 至 `0421.png`：完整大笑。
- `原版笑声.wav`：与素材包并列，可缺省。

加载时检查包大小、条目数、元数据、缺帧和图片尺寸。解码图片缓存最多 16 张；整个动作包保持只读。

## 调眼神

`Animation.GazeTarget` 把鼠标相对眼部的位置映射到 `[-1,1]` 的二维目标，使用 `tanh` 平滑限幅；悬停身体、拖动、打开菜单时目标为零。`Advance` 使用与时间步长有关的指数缓动，避免帧率变化导致跟随速度变化。

`Painter.Warp` 的眼部中心为原图宽度的 `.431`、高度的 `.185`，只改变眼内椭圆区域，水平最大约 2.4 像素、垂直约 2 像素。这一校准针对原版 288×368 图像；替换其他角色时，需要重新校准，不能只改文件名。

视觉修改后必须查看 `--render` 的预览。若想显著增大眼球转动幅度，建议准备独立眼白/瞳孔图层或多个方向的真实素材；继续放大局部变形会降低质感。

## 增加动作

先准备统一画布、透明背景、相同脚底基准的连续帧，记录帧率和总时长，再在 Theme、Animation、Painter 中分别增加素材读取、状态切换和渲染分支。始终按经过时间选帧，明确拖动、双击和全屏隐藏如何打断动作。

1.1 版还支持 `.nct` 多动作主题包，格式见 [主题与动作](主题与动作.md)。GIF 或视频需要先拆帧、去背景和对齐，再打包；程序不会把带有手机界面的录屏直接当成透明桌宠播放。

## 透明窗口参考

实现遵循微软 [UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow) 的逐像素透明接口；画面使用预乘 Alpha，渲染完成后释放临时 GDI 对象。窗口不抢焦点，透明像素点击穿透。
